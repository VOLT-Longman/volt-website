# 성계지도 화면 (#starmap)

2026-11-19 작성. 무역·임무·채광 화면에 글자로만 나오는 장소가 **실제로 어디에 있는지** 보여 주는 화면이다. 구경용 지도가 아니다:
다른 화면에서 장소·경로를 들고 들어오고(3절), 고른 장소에서 다시 그 화면들로 나간다(4절).

- 자료 계약: `docs/starmap-data.md` · 그림 계약: `docs/starmap-assets.md` · 공용 약속: `docs/helper-tools.md`
- 파일: `js/starmap.js`(틀: 함대원 확인 뒤 `init`, 목록·검색·정보 칸·주소, 다른 화면용 `links`), `js/starmap-viewer.js`(3D, ES 모듈), `css/starmap.css`, `tests/smoke/starmap.spec.js`, `tests/smoke/starmap-links.spec.js`(다른 화면 ↔ 지도 링크)
- 아래에서 "확인함"이라고 쓴 것은 `tests/smoke/starmap.spec.js` 또는 직접 찍은 화면으로 본 것이다. 실행 중인 게임과 비교한 것은 하나도 없다.

## 1. 임시 공개

2026-11-20부터 로그인 없이 지도와 행성 원본 그림을 열 수 있다. 다른 도움 도구와 함께 `FLEET_TOOLS_REQUIRE_MEMBERSHIP=true`로 다시 잠근다. 그림은 비공개 R2에서 사이트를 통해 전달하며, 서비스 워커에는 저장하지 않는다. VOLT AI는 기존 로그인 규칙을 따른다.

## 2. 어떻게 그리는가 (화면에도 적혀 있다)

실제 비율로는 그릴 수 없다(허스턴 반지름 1,000 km, 항성까지 1,285만 km). 그래서 단계로 나눠 그리고, **실제 거리는 항상 숫자로** 보여 준다.

| 대상 | 그리는 법 | 실제 값인가 |
|---|---|---|
| 항성 → 행성·정거장·라그랑주 포인트·점프 포인트 | 실제 비율 그대로(가장 먼 곳 = 1000 단위). 높이(z)도 그대로 | 방향·비율 모두 실제 |
| 천체 크기 | 그린 반지름 = 0.9 × (실제 반지름 ÷ 250 km)^0.45 단위. 멀리서는 화면에서 최소 크기(행성 7px, 위성 4px)를 지킨다 | 크기는 실제가 아님 |
| 천체 둘레(위성, 궤도 정거장) | 방향은 그대로, 거리 = 그린 반지름 × (실제 거리 ÷ 실제 반지름)^0.45. 50만 km 밖은 거기서부터 실제 비율로 이어 붙임 | 방향만 실제 |
| 표면 장소 | 그 방향으로 구 표면 위에 찍음 | 방향(위도·경도)만 실제 |
| 궤도 원 | 게임이 궤도 선을 그리는 천체(`orbit: 1`)에, 부모에서 그 천체까지의 거리로 그은 **안내선** | 움직임 아님 |
| 세로 선 | 궤도면에서 6 단위 넘게 떨어진 정거장·점프 포인트에서 평면까지 | 높이 표시 |
| 소행성 고리 | 게임 수치(`rings`)는 면, 우리가 잰 것(`band`, 추정)은 점선 원 + 이름 끝 `*` | 표 참조 |

- **아무것도 움직이지 않는다.** 게임 파일에 궤도 운동이 없다. 구도 돌리지 않는다.
- 좌표: 게임 `(x, y, z)` → three.js `(x, z, -y)`. 그림은 `docs/starmap-assets.md` 대로 `SphereGeometry` 를 -90도 돌려 입힌다.
- 천체가 계 좌표에서 돌아가 있는 각도(예: 마이크로텍 180도, 파이로 전체 약 -85도)는 표면 장소의 두 좌표(`pos`, `rel`)에서 구해 그림에만 적용한다. 장소 표시는 `pos` 방향을 쓴다.
- 그림 속 지형과 장소 표시의 동서 맞춤은 **추정**이다(게임 지도는 그림을 계속 흘려보낸다). 화면의 "어떻게 그렸나요"에 적었다.
- 빛은 입체감용이다. 낮·밤을 뜻하지 않는다(어두운 쪽 장소도 읽히게 주변광을 세게 했다).
- 지금 보는 항성계 하나만 올린다. 그림은 512 를 그 항성계 천체 수만큼, 1k 는 **고른 천체 하나만**(다른 천체로 옮기면 버린다). 2k·4k 는 없다(확인함).
- 필요할 때만 그린다(카메라가 움직이거나 상태가 바뀔 때). 화면 밖·다른 탭이면 그리지 않고, 다른 화면으로 가면 WebGL 자원을 버리고 돌아오면 다시 만든다(확인함). `prefers-reduced-motion` 이면 카메라가 바로 옮겨 간다.
- WebGL2 를 못 쓰면 안내 한 줄과 함께 목록·검색·정보 칸·경로 요약만으로 쓴다(확인함). 오류 화면은 없다.

보이는 것: 기본은 게임 지도에 나오는 곳(`h` 없음)과 점프 포인트. "게임 지도에 안 나오는 곳도 보기"를 켜면 전부. "할 일로 거르기"(무역·정제·채광·임무)를 켜면 그 연결이 있는 곳만(숨은 곳 포함).
주소로 들어온 장소(focus·route·mark)는 거르기와 상관없이 항상 보인다.

## 3. 주소 — 다른 화면이 들어오는 길

`#starmap?<key>=<value>&…` (`VOLT_HELPER.buildHash` 형식. 목록은 쉼표).

| 키 | 값 | 하는 일 |
|---|---|---|
| `sys` | `stanton` \| `pyro` \| `nyx` | 볼 항성계. 없으면 focus → route → mark 의 첫 장소가 있는 항성계, 그것도 없으면 `area`/`site` 가 있는 항성계, 내 항성계(공용 선택), 스탠턴 순 |
| `focus` | 장소 하나 | 그곳을 고르고 카메라를 옮긴다. 정보 칸이 열린다 |
| `route` | 장소들, 순서대로 | 번호를 붙여 잇고, 구간마다 실제 직선 거리를 보여 준다. 다른 항성계로 넘어가는 구간은 어느 게이트웨이(점프 포인트)를 거치는지와 양쪽 구간 거리를 보여 준다 |
| `mark` | 장소들 | 그곳들을 강조한다 ("이 상품을 파는 곳", "이 광물이 나오는 곳"). 다른 항성계에 있는 것은 목록에 항성계 이름과 함께 나온다 |
| `area` | 채광 구역 id 들 | 점이 아닌 채광 구역(`mining.json` / `helper.json` 의 `kind: "area"`): 고리·띠와 그 구역이 있는 곳 |
| `site` | 임무 현장 id | `missions.json` `locations[].id`. 놓인 곳, 따로 찍힌 지점, 또는 "… 근처 (정확한 위치 자료 없음)" |
| `m` | `a,b` | 거리 재기의 두 곳 (화면이 쓴다) |
| `hid` | `1` | 게임 지도에 안 나오는 곳도 보기 |
| `off` | 종류들 | 지도에서 끈 종류 (`station`, `outpost`, `asteroid`, …) |
| `with` | `trade,refinery,mine,mission` | 그 연결이 있는 곳만 |

**장소**는 둘 중 하나다.

- 게임 기록 이름: `data/trade/world.json` 의 `locations[].id`·`bodies[].id`, 채광 천체·장소 id, `missions.places` 의 키. 성계지도 자료의 `objects[].id` 와 같다.
- **UEX 터미널 번호**(숫자): 상품 터미널과 정제 터미널. 지도 자료의 `uex` / `uexRef` 로 찾는다. 무역 경로·시세 화면은 터미널 번호를 그대로 넘기면 된다.

모르는 키·모르는 장소는 조용히 넘어간다("찾을 수 없는 장소"라고만 적는다). 위치 자료가 없는 곳(`nopos`)은 지도에 찍지 않고, 기록 이름으로 본 추정 자리(`guess`)가 있으면 그 자리를 강조하고 "추정"이라고 적는다.

JS 입구 (`js/starmap.js`):

```js
window.VOLT_STARMAP.href({ focus: 'Stanton1_Lorville' })                 // '#starmap?focus=Stanton1_Lorville'  (링크 href 용)
window.VOLT_STARMAP.href({ route: [18, 44, 'Stanton2_Orison'] })         // 배열은 쉼표로 이어 준다
window.VOLT_STARMAP.open({ mark: [44, 248], sys: 'stanton' })            // 바로 이동 (VOLT_HELPER.go 와 같다)
VOLT_HELPER.buildHash('starmap', { area: 'AaronHalo' })                  // 같은 결과
```

`js/starmap.js` 는 다른 도우미 화면보다 뒤에 실린다. 화면을 그리는 시점(이용자가 섹션을 연 뒤)에는 `VOLT_STARMAP` 이 항상 있다.

### 3.1 다른 화면 안의 "지도에서 보기" 링크

무역·임무·채광 화면은 장소 옆에 같은 모양의 링크(핀 그림 + "지도에서 보기")를 단다. **지도에 실제로 보일 수 있을 때만** 나온다.

- 판단 자료: `data/starmap/links.json` (72,279바이트, gzip 11,958바이트). `scripts/starmap/build-link-index.mjs` 가 지도 자료(index + 항성계 파일 3개)에서만 만든다.
  위치가 있는 곳(`places`), 위치는 없지만 추정 자리가 있는 곳(`guess`), UEX 터미널 번호 → 장소(`uex`), 채광 구역(`areas`), 임무 현장이 놓인 곳(`sites`).
  위치도 추정 자리도 없는 곳은 목록에 없으므로 링크가 생기지 않는다.
- 다른 화면은 이 작은 파일만 받는다. 항성계 자료·그림·3D 코드는 지도를 열 때 받는다(확인함). 함대원이 아니면 이 파일도 요청하지 않는다(확인함).
- 현재 자료에서 추정 위치로 연결되는 장소는 0곳이다.

```js
const links = window.VOLT_STARMAP.links;
links.load().then((ready) => { if (ready) redraw(); });   // 화면 init 에서 한 번. 못 받으면 false, 링크 없이 그대로 쓴다
links.button({ focus: 12 }, { name: '에어리어 18' })          // HTML 글자. 보일 것이 없으면 ''
links.button({ route: [1, 12, 4] })                         // 순서대로. 둘 이상이 지도에 있어야 나온다
links.button({ mark: [1, 12, 999] }, { count: true })       // 지도에 있는 곳만 남기고 "N곳"을 붙인다 (최대 140곳)
links.button({ mark: ['Stanton1'], area: ['AaronHalo'] })   // 천체는 mark, 점이 아닌 채광 구역은 area
links.button({ site: 'RestStop_Stanton_4_PortTressler' })   // 임무 현장 하나
links.node(params, opts)                                    // 같은 링크를 요소로 (무역플래너처럼 innerHTML 을 안 쓰는 화면)
links.place(token) / links.area(id) / links.site(id) / links.target(params)   // 직접 확인할 때
```

모양은 `css/starmap.css` 맨 아래의 `.volt-map-link` 한 묶음이다(다른 화면 안에 놓이므로 이 묶음만 `.starmap-app` 으로 시작하지 않는다). 높이 44px.

| 화면 | 링크가 붙는 곳 | 여는 값 |
|---|---|---|
| 무역 경로 | 목록의 줄마다, 경로 자세히의 머리, "이어서 하기" | `route=사는 곳,파는 곳` |
| 여러 곳 돌기 | 결과 카드, 계획 자세히, 섞어 싣기 계획, 지금 실은 화물 팔 곳 | `route=들르는 곳 전부` (출발지로 돌아오면 끝에 출발지), 팔 곳 한 곳이면 `focus` |
| 시세 | 상품: 머리(사는 곳+파는 곳), "살 수 있는 곳", "팔 수 있는 곳" · 거래소 목록의 줄 · 거래소 한 곳 | `mark=터미널들` · `focus=터미널` |
| 임무 | 임무 장소: 줄마다(후보 한 곳이면 `site`, 여럿이면 `mark`) + 전체(싣는 곳·내리는 곳이 한 곳씩이면 `route`, 아니면 `mark`) · 임무가 나오는 곳 · 장소 조건 줄 | `site` · `mark` · `route` · `focus` |
| 운송 계약 | 계약이 나오는 지역 칸 | `mark=그 지역의 천체들` |
| 채광 | 광물(나오는 곳 전부) · 장소 · 정제소 찾기의 줄 | `mark`+`area` · `focus` 또는 `area` · `focus` |
| 무역플래너 | 이번 운송 계획 (함대원에게만) | `route=사는 곳,파는 곳` |

링크가 없는 곳과 이유는 6절.

## 4. 정보 칸 — 다른 화면으로 나가는 길

연결 자료가 있을 때만 링크를 보여 준다.

| 조건 (지도 자료) | 링크 | 주소 |
|---|---|---|
| `uex` (UEX 상품 터미널마다) | 여기서 사고파는 상품 보기 | `#market?t=<터미널>` |
| `uex` | 여기서 출발하는 무역 경로 | `#routes?from=<터미널>` |
| `mission: 1` 이거나 임무 현장이 이곳에 놓여 있음(`sites[].at`) | 이곳의 임무 | `#missions?place=<id>` — 임무 화면이 이곳에서 나오는 임무(지역이면 그 지역에 든 곳)와 이곳이 임무 장소 후보인 임무만 보여 준다. 조건 줄에 장소 이름, "장소 조건 풀기", 다시 지도로 가는 링크가 있다 |
| `mine: 1` | 여기서 나오는 광물 | `#mining?loc=<id>` |
| `areas` (구역마다) | 여기서 나오는 광물 · 구역 이름 | `#mining?loc=<구역 id>` |
| `refinery: 1` | 정제소 찾기에서 보기 | `#mining?tab=ref&ref=<장소 id>` |

그 밖에 보여 주는 것: 종류, 속한 곳, 있는 천체, 표면 위치(위도·경도, 기준선은 우리가 정한 것), 관할, 시설, 항성에서의 실제 거리, 부모 천체에서의 실제 거리, 반지름, 퀀텀 도착 거리.
자료에 없는 값은 "게임 자료에 없음". 점프 포인트·게이트웨이 정거장에는 "○○로 이동" 버튼이 있다(쓸 수 있는 3쌍만; 나머지는 "쓸 수 없음").

거리 재기: 두 곳을 고르면 같은 항성계면 직선 거리, 다르면 "직선 거리는 잴 수 없음" + 게이트웨이까지의 두 구간.
공용 선택(`VOLT_TRADE_ENGINE.state`)에 내 함선이 있으면 `VOLT_TRADE_ENGINE.travel.quantumTravel` 로 퀀텀 이동 시간을 **추정**으로 보여 준다
(그 함선의 기본 퀀텀 드라이브, 직선 거리, 점프 시간은 넣지 않음). 같은 천체의 두 곳은 계산하지 않는다.

## 5. 메뉴에 둔 자리

"임무 · 채광 · 제작" 묶음의 네 번째(데스크톱 메뉴, 모바일 메뉴 두 칸 목록, 바닥글, 통합 검색, sitemap).
지도가 이어 주는 세 화면 중 둘(임무·채광)이 이 묶음에 있고, "무역" 묶음은 이미 다섯 개라서다. 맨 위 줄에 따로 두기에는 자리가 없다.

## 6. 하지 않은 것 · 확인하지 못한 것

- "지도에서 보기" 링크가 **없는 곳** (2026-11-19 자료 기준, 숫자는 자료에서 센 값):
  - 무역: UEX 터미널 161개 중 게임 장소와 잇지 못한 3개(Port Olisar, Shady Glen, UEX Station — 게임에 그런 장소가 없음). 그 터미널이 낀 경로에도 링크가 없다. 나머지 158개와 정제 터미널 20개는 모두 링크가 있다.
  - 시세: 상품 가격 표·가격 변동 표의 줄마다는 달지 않았다(표 위의 "N곳" 링크와 거래소 화면의 링크로 간다).
  - 임무: 임무 장소 줄 3,803개 중 1,919개에 링크. 1,781개는 후보 목록이 임무 자료에 없고(개수만 있음), 103개는 후보가 지도에 놓인 곳이 없다. 임무 2,259개 중 1,903개에 링크가 하나 이상 있다. 임무 목록의 카드·표에는 달지 않았다(임무를 열면 나온다). 변형 임무(`v`)의 장소에도 달지 않았다.
  - 운송 계약: 290개 중 211개. 나머지는 지역이 "RegionA" 같은 이름뿐이라 어느 천체인지 자료에 없다.
  - 채광: 장소 43곳 중 40곳. `Pyro_AkiroCluster`(위치 자료 없음), `Lagrange_G`·`Lagrange_Occupied`(지도 자료에 구역으로 잡히지 않음)는 없다. 이벤트·동굴·시설 표(40개)는 지도 자료와 잇는 키가 없어 없다. 장소 타일과 장소 표의 줄에는 달지 않았다(장소를 열면 나온다). 광물 33종과 위치가 확인된 정제소 19곳에 지도 링크가 있다. 위치가 없는 파이로 정거장 12곳은 정거장 목록과 검색에만 표시한다. 지도 점과 무역·정제 바로가기는 없다.
- 무역·임무·채광 화면에서 지도를 열면 상단의 **이전 화면으로 돌아가기**로 방금 보던 조건과 장소를 다시 연다. 직접 받은 지도 주소에서는 이 버튼이 생기지 않는다.
- 같은 기록의 다른 놓임(`more`)과 임무 현장의 `alt` 는 그리지 않는다. 정거장의 궤도 안내선(`orbit: 1` 인 정거장 22곳)도 그리지 않는다(행성·위성만).
- 천체 보기에서 위성까지 한 화면에 들어오지는 않는다. 구와 표면 장소를 크게 보여 주는 쪽을 골랐다. 멀리 빼면 위성이 나온다.
- 게임 화면과 비교하지 않았다: 위치·거리·방향, 파이로의 방향, 그림과 장소의 동서 맞춤.
- 실제 휴대폰·실제 GPU 에서 보지 않았다. 확인은 Chromium(SwiftShader) 390px 터치 에뮬레이션이다.
- 실제 Cloudflare(R2·Pages)에서 그림이 내려오는 것은 보지 않았다(로컬 폴더로 확인).
- 시세·무역 경로 화면으로 나간 뒤의 모습은 **고정해 둔 가격 자료**로 확인했다(`tests/smoke/starmap-links.spec.js`: 그 거래소 화면이 열리고, 무역 경로는 사는 곳이 그 터미널로 정해진다). 실제 UEX 응답으로는 보지 못했다.

## 게임 패치 뒤 갱신

게임 자료·한국어 패치로 위치 목록을 다시 만드는 명령은 [자료 생성 안내](starmap-data.md), 행성 그림을 내보내고 검증하는 명령은 [비공개 그림 관리](starmap-assets.md)에 있다. 로컬에서 연결 목록과 그림 버전을 맞춘 뒤 전체 시험을 실행한다. 비공개 보관함에 올릴 때는 운영자 승인 뒤 60개를 다시 받아 파일별 SHA-256을 대조한다.
