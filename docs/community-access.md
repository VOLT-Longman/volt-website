# 커뮤니티 멤버 전용 도구

함선DB, 무역플래너, 함선 로드아웃은 Discord 로그인과 VOLT Discord 서버의 **커뮤니티 멤버 역할**을 모두 확인한 뒤 연다. 다른 역할이나 CMS 관리자 권한은 이 조건을 대신하지 않는다. 공개 소개, 공지, 일정, 가입 안내는 기존대로 볼 수 있다.

## 운영 설정

Cloudflare Pages의 운영/미리보기 환경에서 기존 Discord OAuth 및 D1 설정을 유지한다.

- 소유자가 확인해 전달한 커뮤니티 멤버 역할 ID를 서버 기본 설정(`functions/_shared/community-access.js`)에 등록했다. 역할 ID는 비밀값이 아니며, 이름이 바뀌어도 동일 역할을 확인한다.
- 다른 환경에서 운영할 때는 `DISCORD_COMMUNITY_ROLE_ID`로 기본값을 명시적으로 덮어쓸 수 있다. 값을 명시적으로 비우면 접근을 닫는다.
- `DISCORD_ROLE_MAP`은 역할 이름 표시에만 쓰며 도구 사용 권한을 부여하지 않는다. 다른 역할이나 비슷한 이름을 가진 역할은 허용하지 않는다.
- `/auth/me`의 `features.communityConfigured`로 연결 여부만 확인할 수 있다. 역할 ID나 비밀값은 이 응답에 포함하지 않는다.
- `DISCORD_GUILD_ID`는 VOLT 함대 서버여야 한다. OAuth의 `guilds.members.read` 범위로 **해당 서버** 멤버 정보와 역할을 조회한다.
- Cloudflare Pages Functions의 요청 한도 초과 동작은 **Fail closed**로 운영해야 한다. Fail open이면 플랫폼이 함수를 실행하지 않고 정적 자료를 제공할 수 있다. 이 설정은 저장소로 확인/변경할 수 없다.

역할 ID는 2026-11-17 소유자 제공값을 사용했다. 실제 Discord 역할 목록 및 Cloudflare Fail closed 설정은 직접 확인하지 못했다. 계정의 역할 부여/회수는 사이트가 수행하지 않으며 Discord 서버 운영 절차를 따른다.

CMS는 기존 관리자 인증을 적용하는 별도 `/api/admin/ship-source/*` 경로로 필요한 함선 원본만 읽는다. 관리자 로그인만으로 공개 도구의 멤버 제한을 통과하지는 않는다.

## 사용자 동작

1. 제한된 기능에 들어가면 로그인, Discord 참여, 역할 안내를 보여 준다.
2. 로그인 완료 후 원래 기능 경로로 돌아온다. 허용 경로는 함선DB/무역플래너/로드아웃/CMS로 고정하며 외부 주소로 돌아가는 값은 받지 않는다.
3. 역할을 받은 뒤 **권한 다시 확인**을 누르면 새로고침 없이 현재 기능을 연다. 반복 클릭에 따른 Discord 과호출을 막기 위해 최근 확인 후 5초 이내에는 결과를 재사용한다.
4. 일반 서버 요청의 멤버 확인 유효시간은 최대 5분이다. 열린 도구도 1분 간격 및 페이지 복귀 시 상태를 확인한다. 역할 회수·서버 탈퇴가 반영되면 화면을 잠그고 열려 있던 함선 상세를 닫는다.
5. 인증 서버 장애 시 잠금 상태와 재시도 안내를 표시한다. 키보드 포커스는 잠긴 콘텐츠에 남기지 않는다.

## 서버와 캐시

`functions/_middleware.js`가 다음 요청을 **캐시·정적 파일 처리보다 먼저** 검사한다.

- `/api/uex/*`
- `/data/loadout/*`
- `/data/canonical/*`
- `/data/ship-live-stats.js`, `/data/ship-market.js`

경로를 한 번 디코딩하고 연속 슬래시·역슬래시·점 세그먼트를 정규화한 다음 검사한다.
중첩 인코딩이나 잘못된 경로는 400으로 거절한다. `_routes.json`은 `/*`를 포함하여
`//data/…`처럼 검사 함수 자체를 건너뛰던 주소도 먼저 검사한다. 공개 경로는 세션 조회 없이 통과한다.
모든 요청이 Functions 호출에 포함되므로 기존보다 호출량이 증가한다.
경로별 제외 규칙을 다시 추가하려면 정적 파일 해석과 경로 정규화가 동일함을 먼저 검증해야 한다.
근본적으로 자료를 정적 배포에서 분리하는 작업과 플랫폼의 Fail closed 설정 확인은 별도 과제다.
서비스 워커도 변형 경로에서는 기존 캐시를 읽지 않으며 20261117-17에서 이전 캐시를 지운다.

비로그인은 401, 역할 부족은 403, 확인 장애/역할 연결 미설정은 503이다. 성공과 거절 응답 모두 `private, no-store`로 내보내고 `Vary: Cookie`를 붙인다. 내부 UEX 캐시는 인증을 통과한 요청 사이에서 공유한다. 서비스 워커는 보호 자료를 저장/반환하지 않고 새 캐시 버전 활성화 시 이전 VOLT 캐시를 삭제한다. JSON 요청도 브라우저 캐시를 사용하지 않는다.

공개 GitHub 저장소에 포함된 코드·게임 자료의 배포까지 비공개로 만드는 변경은 아니다. 이미 내려받은 자료를 회수할 수도 없다. 이 정책의 범위는 VOLT 웹사이트의 기능 및 자료 요청이다.

## 검증

- `tests/functions/community-access.test.mjs`: 소유자 제공 기본 역할·환경변수 우선·빈 값 차단·역할 이름 및 관리자 예외 없음, 보호 경로 GET/HEAD, 캐시 이전 거절, 공개 경로 유지, 역할 부여/회수/서버 탈퇴/인증 장애, 허용된 OAuth 복귀 주소.
- `tests/functions/service-worker-cache.test.mjs`: 보호된 자료의 캐시 우회와 이전 캐시 삭제.
- `tests/smoke/community-access.spec.js`: 세 기능의 비로그인 차단, 보호 자료 요청 없음, 역할 재확인 후 열기, 역할 회수 후 상세 닫기, 오류/미설정 안내, 모바일 영어와 접근성.

실제 Discord 멤버 계정으로 로그인·역할 부여/회수하는 운영 검증은 별도로 필요하다. 자동 검사에서는 해당 응답을 모의한다.
