# CMS 검색, 이력, 이미지 정리

## 운영 적용 순서

코드 푸시는 D1 마이그레이션이나 운영 파일 정리를 실행하지 않는다.

1. 운영 D1 전체를 내보내 백업하고, `schema_migrations`로 적용 번호를 확인한다.
2. 아직 0014를 적용하지 않았다면 이번 버전의 `0014_cleanup_orphan_event_rsvps.sql`을 적용한다. 삭제된 일정의 참가 기록을 `event_rsvps_orphan_backup`에 먼저 보관한다. 이미 적용했다면 다시 적용할 필요는 없으며, 예전에 삭제된 기록은 새 코드만으로 복원할 수 없다.
3. `0015_cms_history.sql`을 적용한다. 기존 콘텐츠의 시작 시점 스냅샷을 저장하고 이후 작성·수정·삭제를 트리거로 기록한다. 콘텐츠 변경과 이력 저장은 하나의 DB 트랜잭션이다. 재실행해도 시작 시점 이력이 중복되지 않는다.
4. 관리자에서 메뉴별 목록 검색·페이지 이동과 변경 이력 조회를 확인한다.
5. 상단 **이미지·데이터 정리** 작업 영역에서 **데이터와 이미지 정리**를 펼쳐 후보를 확인하고 필요한 작업을 수행한다.

예시(실제 DB 이름으로 치환):

```powershell
npx wrangler d1 export <DB이름> --remote --output=volt-before-cms-history.sql
npx wrangler d1 execute <DB이름> --remote --file=migrations/0014_cleanup_orphan_event_rsvps.sql
npx wrangler d1 execute <DB이름> --remote --file=migrations/0015_cms_history.sql
```

백업에는 운영 개인정보가 포함될 수 있으므로 저장소에 커밋하지 않는다. 전체 백업과 복원 절차는 [운영 문서](OPERATIONS_RUNBOOK.md)를 따른다.

## 관리자 화면 사용

- **콘텐츠 편집**과 **이미지·데이터 정리**를 상단에서 전환한다. 작업 영역을 바꿔도 작성 중인 폼은 보존된다. 저장·업로드 중에는 전환을 잠근다.
- 편집 제목 아래에 선택한 콘텐츠 이름이 표시된다. 상태 표시는 새 콘텐츠, 저장된 콘텐츠, 미저장 변경, 처리 중, 완료, 오류를 구분한다.
- 공지의 영어 입력과 미리보기는 필요할 때 펼친다. 영어 내용이 있는 공지를 수정하면 영어 입력이 자동으로 펼쳐진다.
- 모바일에서는 저장·취소·삭제 버튼이 화면 아래에 고정된다. 목록 항목을 선택하면 편집 화면으로 이동한다.
- 변경 이력은 콘텐츠 편집 영역 아래에서 조회한다. 정리 작업은 별도 작업 영역에서 실행한다.

## 목록 검색과 페이지 이동

- 일반 CMS 목록은 한 페이지에 20건을 조회한다. 제목·내용·이름 등 메뉴에 맞는 필드를 검색한다.
- 검색 입력과 페이지 이동은 편집 중인 폼을 유지한다. 메뉴를 바꾸거나 다른 항목을 열 때 기존 미저장 확인이 작동한다.
- 함선DB는 기존 canonical 검색과 목록을 사용하고 화면 출력만 20건씩 나눈다.
- 관리자 API의 `page` 쿼리는 선택 사항이다. 쿼리를 보내지 않는 기존 호출과 공개 API는 전체 목록 계약을 유지한다.

## 변경 이력과 복구

- 현재 메뉴의 이력을 최신순으로 20건씩 조회한다. 삭제한 콘텐츠도 이력에서 찾을 수 있다.
- 변경 전·후 내용을 확인한 뒤 원하는 버전으로 복구한다. 복구 자체도 새 이력으로 기록된다.
- 이력 조회 이후 다른 관리자가 저장했으면 복구 요청은 409로 거부된다. 최신 이력을 다시 조회한다.
- 관리자 인증은 공용 계정이다. 개인 작업자 식별은 지원하지 않는다. 트리거는 관리자 화면 이외의 DB 수정도 기록하므로 개인 신원을 추정하지 않는다.
- 삭제된 일정의 참가 기록은 콘텐츠 복구로 되살리지 않는다. 참가 기록 복구는 운영 백업을 별도로 확인한다.
- 0015 적용 전의 변경 내용은 소급 복구할 수 없다. 미적용 DB에서는 기존 CRUD가 계속 작동하며 이력 조회에 적용 안내가 표시된다.
- 이력에 포함된 이미지도 사용 중인 파일로 취급한다. 현재 글에서 삭제했더라도 복구에 필요한 이미지는 R2에 보존된다.
- 이력은 자동 삭제하지 않는다. 보존 기간을 정하기 전에는 이력과 이미지 일괄 삭제를 하지 않는다. 기록량이 커지면 별도 보관·만료 정책이 필요하다.

## 기존 갤러리 썸네일 최적화

- 별도 썸네일이 없는 항목에 최대 640px WebP 썸네일을 생성한다. 원본 이미지와 게시 상태·제목·정렬 등은 보존한다.
- 생성 결과가 원본보다 작을 때만 업로드한다. 처리 결과에 성공·건너뜀·오류 및 용량 절감 합계를 표시한다.
- 업로드 성공 후 저장에 실패하면 새 썸네일을 정리한다. 다른 관리자가 수정한 항목은 덮어쓰지 않는다.
- 운영 R2 공개 주소 아래의 CMS 생성 파일만 자동 처리한다. 외부 주소·이전 형식 파일은 오류 목록에서 확인하고 개별 처리한다.
- 파일을 순서대로 처리한다. 작업 중 페이지를 닫으면 남은 항목은 다음 실행에서 처리할 수 있다. 이미 별도 썸네일이 있는 항목은 제외된다.

## 참가 기록과 미사용 이미지 정리

- **참가 기록 백업 후 정리**는 존재하지 않는 일정에 속한 참가 기록만 백업 테이블에 보관한 뒤 삭제한다. 백업과 삭제가 함께 성공하거나 함께 취소된다.
- **정리 후보 확인**은 R2의 `gallery/`를 100개씩 조사한다. 다음 파일 확인 버튼으로 스캔을 이어갈 수 있다.
- 현재 콘텐츠, 변경 이력에서 참조하는 이미지와 업로드 후 24시간 이내의 파일은 후보에서 제외한다.
- CMS가 생성한 파일명 규칙을 만족하는 파일만 후보로 삼는다. 외부·정적·알 수 없는 이전 파일은 삭제하지 않는다.
- 삭제할 후보를 직접 선택한다. 한 번에 최대 100개를 처리하고 삭제 직전 사용 여부를 다시 확인한다.
- 파일 삭제는 영구 삭제다. 필요한 원본을 별도로 보관한 뒤 실행한다. DB/R2 사이에 단일 트랜잭션은 없으므로 정리 중에는 다른 관리자가 과거 미사용 이미지 URL을 새 콘텐츠에 붙여 넣지 않도록 한다.

## 이번 작업의 운영 상태

2026-10-04 운영 `volt-cms-db`의 사용자 테이블을 백업하고 복원 검증한 뒤 누락된 스키마를 적용했다. 기존 콘텐츠의 시작 이력 160건과 변경 트리거 21개, 인증 보안 테이블, 참가자 조회 인덱스를 확인했다. 0010은 기존 열을 확인해 적용 대장만 보정했다. 정리할 참가 기록은 0건이므로 0014의 삭제 절차는 실행하지 않고 백업 테이블만 준비했으며, 0014를 완료로 등록하지 않았다. 기존 이미지 변환과 영구 파일 삭제는 실행하지 않았다. 자세한 적용 상태는 [Cloudflare 운영 설정 기록](CLOUDFLARE_CONFIGURATION.md)을 참고한다.
