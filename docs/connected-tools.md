# 함선·장착·운송·채광·제작 연결 (2026-11-19)

## 화면 흐름

- 함선 DB와 로드아웃에서 고른 함선은 `이어서 보기`에 남는다. 장착 구성은 해당 함선을 다시 열 때 기존 A/B·전원·부품 편집 상태를 사용한다.
- 채광선과 운송 함선은 구분한다. 원광 적재 공간을 일반 화물칸으로 더하지 않는다. 운송 함선은 기존 플래너의 선택·저장 기능을 사용한다.
- 부품 상세 → 제작 → `제작 계획에 추가`에서 여러 부품의 재료를 합산한다. 재료별로 캐는 곳 또는 UEX 상품 검색에 연결한다.
- 채광 광물 상세 → `팔 곳 찾기`는 검증된 정제 후 상품명을 UEX의 유일하게 일치하는 상품명과 연결한다. 애매하면 자동으로 다른 상품을 선택하지 않는다.
- 무역에서 사용할 자금과 운송할 양을 입력하면 구매 → 적재 → 판매 순서로 표시한다. 보유 상품 판매 모드에는 원가가 없으므로 판매액만 나온다.
- `판매한 곳에서 다음 운송 찾기`는 그 장소에서 판매 중인 상품을 조회하고, 선택한 상품의 구매처를 해당 장소로 유지한다. 구매처 가격이 없어진 경우 다른 장소로 바꾸지 않고 안내한다.
- 선택 정보는 같은 브라우저 탭의 세션에 보관한다. 가격은 저장하지 않고 다시 조회한다. 로그인 및 기존 계정별 플래너 저장 정책은 바꾸지 않는다.

## 계산과 자료 경계

`journey-calc.js`는 브라우저와 서버가 공유하는 순수 계산이다. UEX 가격·재고·수요 중 선택 장소의 가격 기준(기본 3일) 이내 보고만 이번 운송 계획에 적용한다. 수량은 요청량, 입력한 화물량, 예산, 알려진 재고와 수요의 최솟값이다. 보고되지 않은 수량과 0을 구분한다. 연료비, 적재 시간, 상자 배치, 시간당 수익은 계산하지 않는다.

### 가격 보고 기준일 (2026-11-19 결정, 아직 화면에는 반영 전)

운영자 결정: 새 도우미 도구(무역 경로·시세·순회 무역·채광 시세)는 기본으로 **3일 이내** 보고를 쓰고, 플레이어가 기준일을 바꿀 수 있으며, 보고가 얼마나 오래됐는지 항상 보여 준다 (`docs/helper-tools.md`, 공용 저장값 `maxAgeDays`).

기존 무역 플래너의 운송 계산은 다음까지만 바뀌었다.


제작은 같은 게임 빌드의 설계도 첫 단계 재료만 합산한다. SCU와 낱개를 분리하며 정제 수율·채굴량·완성품 품질을 추정하지 않는다. 채광 장소는 게임 파일의 암석 구성에 해당 광물이 있는 곳만 연결한다. 모듈 중첩이나 암석 파쇄 가능 여부는 계산하지 않는다. 게임 파일 값은 게임 안에서 실측한 값과 구분한다.

기존 다품목 수익표는 별도 수량 계획이다. 이번 운송 예산을 자동으로 차감하지 않는다는 안내를 표시한다. 새 운송 계산이 준비되면 화물칸 전체 기준의 중복 요약은 숨기고 거래 후보를 유지한다.

## VOLT AI

AI 버튼은 함선, A/B와 개별 전원, 운송 함선, 화물량, 예산, 상품/장소 ID, 광물/채광 장소, 제작 목록의 **선택 정보**를 가져온다. 자동으로 질문을 전송하지 않는다. 이후 화면에서 바꾼 정보는 AI 버튼으로 다시 가져와야 한다.

서버는 이 값들을 검증하고 게임 자료와 UEX를 다시 조회한다. 클라이언트가 보낸 가격·성능·설명은 계산에 쓰지 않는다. 선택한 거래 장소 자료가 없거나 오래되면 금액 계산을 보류한다. 게임 빌드가 서로 다르면 채광·제작·장착 계산을 보류한다. 데이터 기반 검토 결과는 생성 모델로 다시 계산하지 않는다. AI 로그인 정책은 그대로 유지한다.

- `tests/smoke/journey.spec.js`: 1440px/390px에서 제작 → 채광 → 판매처 → 운송 함선 → 예산 → AI → 복귀 → 다음 출발지 → 새로고침, 접근성 및 가로 넘침. 과거 시세와 없어진 출발지 가격도 검사한다.
- 시세와 로그인 응답은 로컬 시험용 값을 사용한다. 실제 사이트 검수 결과는 배포 보고에서 별도로 구분한다.
