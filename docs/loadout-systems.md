# 채광·레이더·전력·터렛 검증 (2026-11-18)

## 자료와 재현

현재 설치된 LIVE `Data.p4k`의 `Game2.dcb`와 `build_manifest.id`를 읽었다. 게임 빌드는 `4.10.200.58746`, changelist는 `13165946`이며 현재 로드아웃 자료와 일치한다. DCB SHA-256은 `005984f5507314a0d5dc3a8d7457bffc03578eeabb1e5da6e6c2d010e81649f4`이다. 원본 대용량 파일은 저장소에 포함하지 않는다.

`research/loadout-data`의 `d25e75d5c6e1881749779e680177aa8bb22f149c`에 있는 `power-profiles.json`의 Online 상태·고정 장비·전력 풀을 같은 빌드인지 검사한 뒤 사용한다. 채광과 레이더는 타입 정보를 보존하기 위해 DCB에서 다시 읽는다. 생성 결과 `data/loadout/comparison.json`은 부품 525종과 함선 222척의 보조 자료이며, 원천 필드·해시·빌드·계산 제한을 기록한다. 화면은 `meta.gameVersion`과 일치할 때만 적용한다.

```sh
node scripts/loadout/build-systems-data.mjs --cache-dir <Game2.dcb와 build_manifest.id가 있는 폴더>
```

기존 `build-comparison-data.mjs` 진입점도 같은 생성기를 호출한다. Erkul 코드·데이터·이미지를 제품에 가져오지 않는다.

## 채광

- `SEntityComponentMiningLaserParams`의 헤드 보정과 `SCItemWeaponComponentParams.fireActions`의 분쇄/추출 빔 출력을 읽는다.
- `EntityComponentAttachableModifierParams`에서 활성 방식, 지속 시간, 사용 횟수와 각 `ItemWeaponModifiersParams.fireActionIndex`의 `damageMultiplier`를 읽는다. 보정값의 `FloatModifier*` 타입도 보존한다.
- 헤드별로 현재 장착된 모듈만 적용한다. 상시 적용과 활성형을 구분하고, 활성형은 사용자 토글을 켰을 때만 적용한다. 상위 전원이 꺼진 헤드는 출력 0이다. 활성화는 성능 미리보기이며 게임의 시간 경과나 사용 횟수 차감을 시뮬레이션하지 않는다.
- 출력 채널마다 비중립 배수가 하나일 때만 `헤드 기본 출력 × 배수`를 계산한다. 여러 모듈이 같은 채널에 기여하거나 값이 누락되면 결과를 `출력 계산 미확인`으로 표시한다. 중립값 1은 중첩 기여로 세지 않는다.
- 저항·불안정성·최적 구간·충전 속도는 헤드와 모듈의 개별 출처를 보여 준다. `Multiplicative`라는 타입명만 보고 `(1+a)×(1+b)` 등의 합성식을 추측하지 않는다.
- 모듈 교체 시 그 자리의 활성 상태를 초기화한다. 전력 계획과 활성 상태는 함선별 저장, 이름 붙인 저장, 공유 URL `op`, A/B, 실행 취소/다시 실행에 포함한다. 구성 비교에는 계산 가능한 채광 출력과 전력 예산도 표시한다.

내부 브라우저에서 Erkul 프로스펙터를 실제 조작한 표본: Arbor 기본 2,340, Rieger Mk1 2,691, Surge 비활성 2,340 → Engage 후 3,510. 자체 원본 배수 1.15/1.5와 일치한다. Erkul의 최적 구간·저항 표시는 단순 곱셈 가정과 일치하지 않았다. 게임 안 동일 조건의 실측이나 다중 모듈 합성은 아직 확인하지 않았다.

## 레이더

원본 `SCItemRadarComponentParams.signatureDetection` 순서는 IR, EM, CS, Decibel, Resource, Identity, CommsSignal, Interactable이다. 8종의 민감도·투과 계수·수동/능동 탐지 허용 여부를 보존한다. 화면에서는 주요 IR/EM/CS/자원(RS)의 민감도와 조준 보조 최소/최대/버퍼, 최소 전력을 비교하고 상세에서 투과 계수·탐지 허용·핑 대기 시간을 표시한다.

Ecouter 표본: IR/EM/CS 민감도 0.8, 자원 민감도 1, CS 수동 탐지 불가/능동 탐지 가능, 조준 보조 845~1,105 m, 버퍼 60 m, 핑 2.5초. 내부 브라우저 Erkul 비교표에서 같은 최소/최대/버퍼를 확인했다. **이 거리는 조준 보조 거리이며 실제 표적 탐지 거리가 아니다.** 표적 시그니처, 차폐, 전력 상태를 조합한 탐지 공식은 적용하지 않는다.

## 전력과 캐패시터

현재 구현은 전력 예산 계획이다. 원본 Online 소비량과 `minimumConsumptionFraction`, 함선의 `FixedPowerPool`, 고정 장비 요구량을 사용한다. 종류별 막대/숫자 배정, 공급량·잔여량·초과 표시, 최소 작동량을 지키는 자동 배분을 제공한다. 0은 해당 계획에서 배정하지 않는다는 뜻이며 기존 장비 전원 토글과 별개다. 정격 요구량은 공급량을 넘을 수 있다.

**부분 전력에 따른 탄창 용량·충전 속도·실드 재생률 환산은 구현하지 않았다.** 성능 수치는 기존 정격 계산을 유지하며 이를 패널 안에 표시한다. 배정 0도 총기 DPS를 임의로 0으로 바꾸지 않는다. 실제 장비 전원 끄기는 기존 방식대로 성능에 반영된다.

Erkul의 어벤저 타이탄에서 무기 배정 4→1을 직접 조작했을 때 탄창 25→8, 지속 DPS 1,459→1,170, 순간 DPS 2,360 유지가 관찰됐다. 이는 참고 화면의 관찰값이며 VOLT 환산식의 근거로 사용하지 않았다. 현재 DCB에는 `SCItemWeaponRegenPoolComponentParams` 구조 정의가 있지만 인스턴스가 0개다. 남아 있는 과거 assignment curve를 현재 엔진의 배분 규칙으로 단정할 수 없다. 추가 구현에는 현재 엔진 규칙 또는 통제된 게임 내 실측이 필요하다.

## 터렛 구성

Erkul 아스가르드에서 PC2 듀얼 마운트와 하부 유인 터렛, 각각의 짐벌·무기 펼치기를 직접 확인했다. VOLT에서는 실제 슬롯 트리를 사용해 터렛/랙 상위 카드, 각 하위 마운트·무기, 터렛별 무기 수·순간 DPS, 독립 접기, 상위 전원을 표시한다. 한 자식만 있는 마운트는 같은 행의 두 카드로 연결한다. 고정 마운트에는 교체 버튼을 만들지 않는다. 변경 필터는 변경된 하위 장비의 상위 카드도 남기되 제목에는 실제 말단 장착 자리만 센다.

## 확인 범위

자동 검사는 단일/활성/누락/중첩 모듈, 헤드 간 격리, 222척의 전력 최소값·공급 예산, 공유 입력 정리, 레이더 원본값, 데스크톱/390px의 조작·저장·비교와 기존 구매 흐름을 다룬다. 내부 브라우저에서는 교체 후 실제 출력, 활성 토글, 전력 배정, 터렛 소속과 접기, 판매처 지정·장바구니 연결을 별도로 확인한다. 게임 플레이 실측은 이번 확인 범위가 아니다.
