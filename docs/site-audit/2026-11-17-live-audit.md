## 8. 확인하지 못한 것

- 실제 휴대폰·화면 낭독기·한글 입력기로 눌러 보는 확인은 하지 않았다(6번 포함).
- "보고"로 표시한 항목은 검사 담당의 코드 읽기 결과다. 고치기 전에 한 번씩 재현해 봐야 한다.
- 읽지 못한 부분: 관리자 화면 스크립트(`admin/admin.js`, `admin-tools.js`)는 표본만, `scripts/erkul/*` 와 `scripts/shipdb-rewrite/*` 는 일부만, 화면 테스트 60여 개 중 50여 개는 훑어보기만, 번역 문장의 품질은 보지 않았다.
- Cloudflare 대시보드 설정과 GitHub 브랜치 보호 설정은 저장소에서 보이지 않는다.
- 색 대비는 글자색·배경색이 함께 적힌 규칙만 계산했다(사진·그러데이션 위 글자는 제외).

## 9. 권장 순서

1. **바로 보이는 고장** (1장의 1–5, 8, 9번): 각각 작고 서로 독립적이다.
2. **브라우저 확인 후 수정** (6번 한글 입력): 실제로 깨지는지 먼저 본다.
3. **자료 문제** (7, 11번): 생성기에서 고치고 자료를 다시 만든다.
4. **보안 바닥 다지기**: 공통 관문 하나로 출처 확인·보안 머리글을 한꺼번에 넣고, 관리자 비밀번호 시도에 전체 상한을 둔다.
5. **배포 절차**: 시각 기준을 메인이 아니라 가지에서 만들고, 캐시 버전 누락을 검사에 넣는다.
6. 나머지는 영역별 표의 등급 순.
