원인:

- `functions/_middleware.js` 는 주소가 `/data/loadout/` 로 **시작하는지**만 본다. `/data//loadout/` 은 해당하지 않아 통과시키고, 그 뒤 정적 파일 처리가 빗금을 하나로 접어 파일을 내준다.
- `//data/…` 는 `_routes.json` 의 `"/data/*"` 에 걸리지 않아 검사 코드 자체가 실행되지 않는다.

고치는 방법(둘 다 필요):

1. 검사 전에 연속된 빗금을 하나로 접는다: `path.replace(/\/{2,}/g, '/')`. 테스트에 `/data//loadout/x`, `/data///canonical/x` 를 추가한다.
2. 맨 앞 이중 빗금은 코드가 실행되지 않으므로 Cloudflare 쪽에서 막는다: WAF 사용자 규칙으로 "주소 경로에 `//` 포함 → 차단"(또는 URL 정규화 후 리디렉션). `_routes.json` 을 `"/*"` 로 넓히는 방법도 있지만 모든 요청이 함수 호출로 잡혀 사용량이 늘어난다.

근본 대안: 보호 자료를 공개 정적 파일로 배포하지 않고 함수가 직접 읽어 내주는 구조로 옮긴다(작업량 큼).

## 새로 보인 것

1. **모든 요청이 함수를 거친다.** 우회를 막으려고 `_routes.json` 이 `"/*"` 로 넓어졌다. 사진·스타일 같은 정적 파일 요청도 전부 Pages Functions 호출로 잡힌다. 무료 요금제는 하루 10만 호출이 한도라, 방문이 몰리는 날 한도를 넘을 수 있다. 그때의 동작이 Cloudflare 대시보드의 "Fail open / Fail closed" 설정에 달려 있다: open 이면 잠금 없이 자료가 나가고, closed 면 사이트 전체가 오류가 된다. **대시보드에서 현재 설정과 최근 호출 수를 확인해야 한다**(저장소에서는 보이지 않음).
2. **이 PC(윈도우)에서는 `npm run check` 가 실패한다.** 새로 추가된 "GSAP 파일이 원본과 같은지" 검사가 윈도우의 줄바꿈 변환(CRLF) 때문에 "불일치"로 나온다. 저장소와 라이브의 파일은 원본과 같다(직접 비교). `.gitattributes` 에 `assets/vendor/** -text` 를 넣거나 검사가 줄바꿈을 무시하게 하면 된다. 지금 상태로는 윈도우에서 푸시 전 필수 검사를 통과시킬 수 없다.
3. Cloudflare 가 끼워 넣는 스크립트의 CSP 차단 오류는 그대로다.
4. 스크립트가 32개로 늘었다(GSAP 118KB 포함, 압축 전). 첫 화면에서만 쓰는데 모든 화면에서 받는다.

- 새 연출의 실제 모습(PC·휴대폰).
