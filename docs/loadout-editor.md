# 로드아웃 편집기

현재 채광 출력·레이더 비교·전력 예산·터렛 계층의 구현과 미검증 범위는 [2026-11-18 조사 기록](loadout-systems.md)을 기준으로 한다. 아래 날짜별 기록의 당시 제한 중 일부는 후속 구현으로 갱신됐다.

## 계산기 작업 화면 재설계 (2026-11-17)

- 상단 함선·A/B 구성·저장·공유·실행 취소 다음에 화력, 방어, 비행, 동력 카드를 함께 둔다. 비행 카드는 기본으로 펼친다. 장착 종류 카드는 화면 전체 폭의 그리드를 쓰고 휴대폰은 한 열로 배치한다.
- 장비 이름을 누르면 호환 후보 비교표가 열린다. 기존 변경 버튼도 유지한다. 판매처 버튼은 부품 상세의 판매처 탭으로 바로 연결한다. 교체창에도 현재 함선 화력·실드·소비 전력과 기본 구성 대비 변화를 표시해 목록을 유지한 연속 교체 결과를 볼 수 있다.
- 채광·작업을 별도 분류하고 채광 모듈 슬롯에 종류와 번호를 함께 표시한다. 이름이 내부 클래스명뿐인 랙·마운트는 종류·크기·위치로 표시한다. 변경 필터 제목은 `표시한 슬롯 / 전체 슬롯`으로 구분한다.
- 레이더는 IR/EM/CS 민감도와 조준 보조 최대 거리를 비교하며 상세에는 투과 계수도 표시한다. 조준 보조 거리는 실제 탐지 거리로 해석하지 않는다.
- 채광 모듈은 개별 레이저·추출 출력 배수와 저항·불안정성·최적 구간 보정을 비교한다. 활성형/상시 적용을 구분한다. **헤드와 모듈의 합산식은 미검증이므로 전체 채광 성능으로 계산하지 않는다.**

### 자료·식별 근거

`data/loadout/comparison.json`은 자체 게임 파일 조사 브랜치의 `d25e75d5c6e1881749779e680177aa8bb22f149c`에서 레이더·채광 모듈의 표시용 값만 추출한다. 현재 재생성 명령과 원천은 [조사 기록](loadout-systems.md#자료와-재현)을 참고한다. 원천 경로, 커밋, 빌드, 조사 시각을 기록하며 현재 `meta.gameVersion`과 다르면 화면에 적용하지 않는다. 기존 계산식·게임 데이터·저장/공유 형식과 가격 원천은 유지한다.

MSD-322 일반형(`6bea95f5…`)과 미티어 기본 랙(`27b1b667…`)은 현재 추출된 필드가 클래스명 외에는 동일하다. 그러나 서로 다른 게임 식별자이므로 삭제하거나 alias로 합치지 않고 탐색 목록의 변형으로 묶는다. 펼치면 미티어 기본 랙이라고 표시하며 판매처를 일반형에서 넘겨받지 않는다. 사이클론 MT 랙은 `req: Cyclone_MT` 호환 조건이 있고 차량 랙은 종류·허용 미사일 종류도 다르므로 별개로 유지한다. 미티어 랙의 별도 게임 내 용도까지 검증한 것은 아니다.

### 라이브 비교에서 직접 확인한 범위

내부 브라우저로 VOLT의 스토커 선택 화면과 Erkul의 스토커 기본 화면·무기 카드 클릭 → 정렬 가능한 후보 비교표를 확인했다. VOLT는 오른쪽 요약 열과 별도 변경 버튼 중심, Erkul은 여러 성능/장비 카드와 카드 클릭 중심이었다. 이 차이를 자체 HTML/CSS와 기존 상태 관리로 구현했다. 참고 사이트 소스·데이터·이미지는 가져오지 않았다. 이후 브라우저 응답이 지연되어 참고 사이트의 교체 완료·판매처·장바구니 동작은 이번 조사에서 재확인하지 못했다. 채광 합산, 레이더 탐지 거리, 게임 안 실제 수치는 미검증이다.

함선을 고르고 장착 자리마다 부품을 바꿔 끼우며 화력·방어·동력·양자 항행과 구매 비용을 확인하는 화면이다(`#loadout`).
2026-11-16 1차 구현 기준.

## 자료 갱신 (게임이 설치된 PC에서)

```bash
npm run loadout:build      # 기본 경로의 Data.p4k를 읽는다. 다른 경로는 --p4k <경로>
npm run loadout:ko -- --ini "C:/Program Files/Roberts Space Industries/StarCitizen/LIVE/data/Localization/korean_(south_korea)/global.ini"
npm run test:functions     # 자료 정합성·계산식 검증 포함
```

게임 패치 후 실행한다. 게임 파일 형식이 바뀌면 해석기가 "layout mismatch"로 멈춘다(조용히 틀린 자료를 만들지 않는다).
부품 고유번호(GUID)는 게임 정의의 값 그대로라 UEX의 uuid와 일치한다.

## 함선·부품 고르는 기준

- 함선: `entities/spaceships`·`groundvehicles` 정의 중 이름이 있고, AI·임무·행사·도색·교육용 변형이 아닌 것. 소유자의 함선DB 영구 제외 목록(`ship-catalog-policy.js`)도 따른다.
- 부품: `entities/scitem/ships|vehicles` 정의 중 편집 대상 종류이고 실제 이름이 있는 것 + 함선 기본 장착에 쓰인 것.
- 장착 자리: 함선 구조 XML의 ItemPort와 정의의 Ports. 기본 장착은 정의의 loadout entries(부품 자신의 기본 하위 장착 포함).

## 계산 방식

- 무기 초당 피해: 1발 피해 × 분당 발사 수 ÷ 60. 충전식은 1발 피해 ÷ (충전 + 재사용 대기), 광선은 자료의 초당 피해.
- 1발 피해: 탄이 맞을 때의 피해 + 터질 때의 피해(디스토션 무기·로켓 포드는 폭발 쪽에만 수치가 있다). 0.001 미만의 자리표시 값은 버린다.
- 지속 DPS(`weaponSustain`): 실탄은 1발당 열(`w.heat`)이 과열 한도(`w.oh.max`)에 닿으면 `w.oh.fix`초 쉰다(발사 간격이 `w.oh.start`보다 길면 그 사이 `w.oh.cool`만큼 식는다). 에너지는 축전 탄창(`w.regen.load`)을 다 쏘고 `cd`초 뒤 초당 `perSec`발씩 다시 채운다. 어벤저 스토커 기본 장착 1,460(순간 2,360)으로 대조했다. 파워 배분에 따른 축전 변화는 넣지 않았다.
- 화력 합계에는 기총(`WeaponGun`)만 넣는다. 채광 레이저·디코이 발사기는 뺀다.
- 그 밖의 부품 수치: 폭탄(`ms.dmg`, `ms.radius`), EMP(`emp`), 퀀텀 차단기(`qig`), 채광 레이저(`mine`, 레이저 출력은 `w.beamDps`), 미사일 랙 탑재 수(`rackLoad`).
- 조종사/터렛 구분: 유인 터렛(TurretBase) 아래의 무기를 터렛으로 센다. 원격 터렛을 조종사가 쓰는 함선은 원본의 구분과 다를 수 있다.
- 장착 규칙: 슬롯이 받는 종류·크기 범위 + 전용 부품(requiredTags)은 해당 함선·상위 부품에만. `kind: 'f'`(고정) 슬롯은 바꿀 수 없다.
- 부품을 바꾸면 그 아래 달려 있던 부품(예: 랙의 미사일)은 빠지고, 새 부품의 장착 자리가 빈 슬롯으로 열린다.

## 알려진 한계 (2026-11-16)

- 화력은 자체 계산이다. 게임 안 수치·알려진 값과 표본 대조만 했다(판터 리피터 545.6, 아스가르드 파일럿 3,274, 글라디우스 1,945 등). 전 함선 전수 검증은 아직이다.
- 문 기총(도어 거너)과 유인 터렛은 터렛 화력으로 센다. 다른 도구는 문 기총을 합계에서 빼기도 하므로 총합이 다를 수 있다.
- 퀀텀 항속 거리는 표시하지 않는다(계산식 미검증).
- 함선 변형(modification)의 장착 자리 차이는 기본 구조 XML 기준이라 일부 변형에서 다를 수 있다.
- 파워는 출력과 "모든 장비 최대 가동 시 필요량"만 보여준다. 게임의 파워 배분은 구현하지 않았다.
- 한국어 표기는 임의로 번역하지 않고 게임 한국어 패치를 따른다(퀀텀 드라이브, 파워 플랜트, 쿨러, 실드 제너레이터, 기총 …). 부품 이름은 1,575종 중 615종이 패치 표기로 나오고, 패치에 없는 것은 게임 원문(영문)으로 표시한다. 한국어 이름 아래에 원문 이름을 함께 보여준다. 부품 설명문은 싣지 않는다.
- 상점에서 팔지 않는 부품(군용 등 파밍 전용)도 장착 후보에서 빼지 않는다. "상점 판매 없음 · 파밍 획득"으로 표시하고 구매 합계에서만 제외한다.
- 구매 목록은 바꾼 부품만 최저가 1곳 기준으로 합산한다. UEX에 판매처가 없는 부품은 "판매처 정보 없음"으로 표시한다.
- 로그인 계정에 저장하지 않는다. 브라우저 저장(localStorage)과 공유 링크(`?loadout=<함선>&set=<변경>#loadout`)만 지원한다.


### 장비 탐색과 비교 화면 (2026-11-17)

- 장착 화면에서 전체 장비 또는 무장·방어·이동 계통을 골라 볼 수 있다. 종류를 바꿔도 전체 함선 수치와 장착 상태는 그대로 유지한다.
- 장비 유형별 카드 안에서 위치, 이름, 주요 수치, 교체 동작을 구분한다. 휴대폰에서는 상단 도구 영역을 고정하지 않아 장비 목록을 가리지 않는다.
- 교체 후보에서 현재 장착 부품을 강조하고, 검색·필터 초기화를 제공한다. 이름·가격 및 낮을수록 유리한 수치는 오름차순 정렬로 알린다.
- 계산식과 원본 데이터, 저장·공유 형식은 변경하지 않는다.

### 구매 계획·판매처·출시 목록 (2026-11-17)

- Erkul 라이브에서 부품 구매처 선택 → 담기 → 장바구니에서 상점 변경, 부품 상세 → 교체 → 후보 목록 유지 동작을 직접 확인했다. 소스·테마·계산식은 가져오지 않았다.
- 장바구니에 최저가/다품종 상점 묶기, 품목별 판매처 지정, 방문 순서 이동, 복사, 판매처 새로고침을 추가했다. 장바구니 수량 저장 형식은 유지하고, 상점 지정/방문 순서는 `volt-loadout-plan-v1`에 별도로 저장한다.
- 자동 묶기는 수동 지정 상점을 유지하고 남은 품목을 가장 많이 파는 상점을 고르는 탐욕 방식이다. 동률이면 해당 품목들의 수량을 반영한 합계가 싼 곳을 선택한다. 최저가 합계와의 차이도 표시한다. 전역 최적 방문 수나 최단 이동 시간은 보장하지 않는다.
- 수동 지정 판매처가 사라지면 다른 곳으로 몰래 바꾸지 않고 미확인으로 표시한다. 판매처 미확인 품목은 합계에서 제외한다.
- UEX 레이더 항목에 UUID가 비어 있어 이전 UUID 전용 매칭에서 누락됐다. UUID 우선, UUID가 없는 자료만 원문 이름·크기가 유일하게 일치할 때 연결한다. 크기가 없는 자료는 같은 이름의 제품 자체가 유일한 경우에만 연결한다. 번역 이름·부분 일치로 추측하지 않는다.
- 판매처를 12개로 자르던 제한을 제거하고 terminal ID로 중복 지점을 정리했다. API 캐시는 v2로 갱신하며 새로고침에는 1분 공유 캐시 하한을 둔다.
- 도색 클래스 접미사 `mr숫자`, `CleanAir`, `Shark`가 확인된 무장만 원형 아래에 펼쳐 보여준다. 변종 UUID/성능/가격/저장 값을 원형으로 바꾸지 않는다. 전용 터렛·다른 크기의 무장은 합치지 않는다.

## 2026-11-18 계산기 배치 재구성

내부 브라우저로 현재 Erkul 라이브를 직접 조작했다. 과거 화면 자료와 달리 현재 데스크톱 화면은 상단 함선 검색, 구성 탭, 왼쪽 두 열의 함선/화력/방어/선체/비행 카드, 오른쪽 설명/작업/동력 카드로 구성된다. 장비는 넓은 무장·미사일 영역과 좁은 시스템 영역으로 나뉜다. 마운트와 무기 카드는 연결선으로 이어지며, 교체는 넓은 표, 상세·판매처·장바구니는 오른쪽 패널을 사용한다. 이 배치를 VOLT의 색·폰트·기존 함선 사진으로 직접 구현했다. 참고 사이트 소스·이미지·수치 자료를 제품에 가져오지 않았다.

- 함선 선택 줄은 스크롤 중에도 남는다. 함선 카드가 화면 위로 사라지면 축약 성능 줄이 표시된다. 함선 목록은 선택 줄 아래에 열리며 Escape로 닫힌다.
- 구성 A/B, 저장/불러오기, 공유, 실행 취소/다시 실행, 기본값 복원, 구성 비교를 유지한다. 저장 형식은 바꾸지 않는다.
- 장비 영역은 데스크톱에서 2:1로 나누고, 휴대폰에서는 한 열로 쌓는다. 마운트·랙을 별도 연결 카드로 표시하되 실제 슬롯 개수와 미사일 묶음 교체 규칙은 유지한다.
- 후보 표의 수치 셀을 누르면 바로 교체한다. 상세 링크와 장착 버튼, 정렬, 검색·필터, 일괄 교체, 목록 유지 옵션도 계속 사용할 수 있다. 무기 후보에는 기존 자료의 발사 속도·탄속·탄창·내구도를 추가했다. 현재 마운트 자체에 비교 수치가 없는 경우 호환 후보의 수치 종류로 표를 구성한다.
- 판매처 패널에서 상점을 고른 뒤 ‘담고 장바구니 보기’를 누르면 그 상점을 명시적으로 지정해 담는다. 장바구니는 오른쪽 패널에서 수량·상점·구매 방식·방문 순서를 바꿀 수 있다. 기존 장바구니 탭도 유지한다.
- 현재 Erkul은 폭 980px 미만에서 전체 대시보드를 제한하고 별도 모바일 검색 화면으로 안내한다. VOLT는 사용자의 요청에 따라 휴대폰에서도 함선 선택부터 교체·성능 확인·판매처·장바구니까지 제공한다.

계산·자료 변경은 없다. 라이브에서 Erkul 스토커의 M6A 교체 후 순간 DPS 2,119/알파 1,053을 확인했고, VOLT의 같은 표본도 동일한 두 값을 표시했다. 지속 DPS는 서로 다르며, 일치시키기 위한 보정은 하지 않았다. 채광 모듈 중첩, 레이더 탐지 거리, 전력 배분 등의 미검증 계산은 여전히 합계에 반영하지 않는다. `research/loadout-data`의 `implementation-map.md`, `discrepancies.md`에서 정리한 검증 범위도 유지한다.

## 2026-11-18 가독성과 최소 전력 묶음 (`20261118-10`)

내부 브라우저에서 Erkul Prospector의 전력 분배를 직접 조절하고 원래 값으로 복원했다. 최소 작동 전력은 숫자가 적힌 큰 블록으로, 추가 전력은 작은 칸으로 표시되는 점을 참고했다. 코드·자료·이미지는 가져오지 않았다.

- VOLT의 기존 계통별 최소 전력이 2칸 이상이면 하나의 큰 블록으로 표시한다. 예를 들어 Titan 실드의 최소 4칸은 `4` 블록 하나이며, 그 위에 5·6칸 배정 버튼이 놓인다. 큰 블록을 누르면 최소량 전체가 배정된다. 최소량 아래로 줄이면 기존 규칙에 따라 0칸이 된다.
- 전체 배정 예산은 현재 장착하고 켠 파워플랜트의 기존 계산값을 그대로 따른다. 계통별 합산 모델을 유지하며, Erkul의 개별 부품 단위 표현이나 미확인 성능 곡선을 계산에 이식하지 않는다. 정격 성능과 전력 계획의 구분을 보이는 안내로 유지한다.
- 배정량·남은 전력을 크게 표시하고 세부 계산 설명은 접는다. 전력 분배를 오른쪽 첫 카드에 놓고 함선 기본 정보는 접을 수 있게 정리한다. 상단에 장비 편집·전력 분배 바로가기를 추가하며, 키보드 초점과 스크롤 위치가 고정 메뉴 아래로 이동한다.
- 화력은 순간·지속·일제 사격 값을 강조하고 파일럿/터렛의 순간·지속 DPS를 같은 열로 맞춘다. 장비 이름, 위치, 교체 후보 수치, 행 구분, 선택·전원 상태의 대비를 높인다. 휴대폰의 주요 조작 버튼은 최소 44px로 키우고 전력 계통은 두 열로 배치한다.
- 채광·운송 표의 행 구분과 제목 대비도 보강한다. 데이터, 저장/공유 형식, 로그인 임시 공개 설정은 변경하지 않는다.

자동 검사는 1440px/390px에서 최소 블록의 크기와 배정, 증감, 키보드 접근, 바로가기 위치, 전력 패널 접근성, 교체창의 가로 넘침을 확인한다. 기존 파워플랜트 교체·장비 전원·실행 취소·저장·공유 검사를 함께 유지한다. 게임 안에서 전력에 따른 실제 성능 곡선을 검증한 것은 아니다.
