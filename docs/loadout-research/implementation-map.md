# 구현 지도

항목마다 **지금 있는 것 → 새로 확보한 것 → 고칠 곳 → 지금 구현 가능한 범위 → 보류**를 적습니다.
고칠 곳의 파일 이름은 현재 메인 기준입니다. 이번 조사에서는 그 파일들을 바꾸지 않았습니다.

## 1. 판매처·부품 식별

| | 내용 |
| --- | --- |
| 지금 있는 것 | `functions/api/uex/loadout-prices.js`: 12개 분류, UUID 로 묶은 가격표 + UUID 없는 품목의 이름표. `js/loadout.js` `priceInfo`: UUID → 없으면 이름·규격 일치(후보 1개). `js/loadout-planner.js`: 도색 접미사 3종 묶기. |
| 새로 확보한 것 | `component-identities.json`: 15개 분류 전수 대조. `shop-coverage.json`: 품목별 판매처 원본(UEX 품목 ID·터미널 ID·위치·갱신 시각)과 연결 상태. |
| 고칠 곳 | ① `loadout-prices.js` `ALLOWED_CATEGORIES` 와 `js/loadout.js` `UEX_CATEGORY` 에 30(채광 모듈), 67(트랙터), 110(샐비지) 추가. ② `priceInfo`: 대표 부품을 볼 때 `alias` 가 그 대표인 숨긴 항목의 UUID 도 함께 조회(11건). ③ UUID 가 같아도 이름이 포함 관계가 아니면 연결 보류(5건). ④ 이름으로만 연결한 판매처는 화면에 "이름으로 연결" 표시. ⑤ `scripts/loadout/build-loadout-data.mjs`: 기본 장착에 없더라도 판매되는 부품(예: S0 Helix)을 싣기 — UEX UUID 목록을 입력으로 받는 방식. |
| 지금 구현 가능 | ①–④ 전부. 필요한 자료가 모두 있습니다. |
| 보류 | Observer-Go(규격 불일치), M2C "Swarm"(후보 2개), UUID·이름 후보가 없는 5종. UEX 쪽 정정이 있어야 확정. ⑤는 추출기 변경이라 다른 작업과 겹치지 않을 때. |

## 2. 전력·냉각

| | 내용 |
| --- | --- |
| 지금 있는 것 | `items.json` 의 `power {use, gen}`, `cool {use, gen}`, `em`, `ir` (Online 상태의 합계 한 줄). 화면은 발전량 대비 사용량 합만 보여 줌. |

| 고칠 곳 | 추출기: `minimumConsumptionFraction`, `powerRanges`, `defaultPriority`, 함선 `powerPools` 를 `data/loadout/` 에 싣기. 계산기: 최소·최대 요구 합, 장비별 배정 칸 수 → 계단식 계수. 화면: 장비별 전력 칸 배정, "켜거나 끄기만 되는 장비" 구분. |
| 지금 구현 가능 | 발전량·최대/최소 요구 합, 부족 여부, 장비를 껐을 때 남는 칸, 장비별 배정 칸 수에 따른 계수(0.7/0.85/1) 표시. 고정 장비까지 합친 실제 요구량. |
| 보류 | 부족할 때 게임이 실제로 줄이는 순서, 계수가 곱해지는 성능 항목, 무기 묶음 칸 수 ↔ 탄창·충전 속도, 장비를 끌 때 하위 장비 영향, 부품 온도의 시간 변화. → 게임 안 실측 필요(칸 수별 실드 재생량, 무기 묶음 칸 수별 탄창). |
