# 함선DB 공식 대표 이미지 설계 검토

검토일: 2026-10-18. **설계 검토 완료 / 운영 기능 미구현.** 이번 배포에서 바뀌는 것은 소개·가입 안내의 공식 사진이며, 함선DB 카드와 상세 화면에는 아직 사진을 추가하지 않는다.

## 현재 확인한 구조

- 함선DB UI는 `js/ships.js`, 사실 데이터는 canonical 계층을 사용한다. Erkul 제원 갱신과 이미지 갱신은 별도로 관리해야 한다.
- 현재 이미지 필드나 이미지 인덱스가 없다. RSI 공식 30종의 `sourceUrl`은 존재하지만 Erkul 기반 전체 목록의 사진 연결을 대신하지는 않는다.
- C2 Hercules의 공식 페이지를 실제 조회했다: https://robertsspaceindustries.com/en/pledge/ships/crusader-starlifter/C2-Hercules
- 공개 Product JSON-LD에서 제품명 `C2 Hercules`와 이미지 URL들을 얻을 수 있다. 12개 URL에는 같은 장면의 반응형 크롭도 포함되므로 12개 서로 다른 사진으로 세지 않는다.
- 첫 이미지의 HTTP 200 / image/webp, 1820×1024, 468938 bytes와 실제 C2 장면을 확인했다. SHA-256: `281d0cd54d731ad2995927389bb780cc55de9b635095bb6530733421a2066ce1`. 이는 수집 가능성 확인용이며 전체 함선의 수집·검수 완료를 뜻하지 않는다.

## 권장 구조

별도 `data/ship-imagery.json`에 canonical ID별 대표 사진 한 장을 등록한다. 이름 유사도나 검색 결과 순서로 런타임 자동 연결하지 않는다.

| 필드 | 역할 |
|---|---|
| shipId | 예: `c2-hercules`. canonical에 실제 존재해야 한다. |
| sourcePage / sourceUrl | RSI 공식 제품·갤러리 페이지와 원본 이미지 주소 |
| sourceSha256 / originalWidth / originalHeight | 원본 변경과 실제 해상도 확인 |
| thumbnail / detail / width / height | 로컬 WebP 썸네일·상세 파일과 레이아웃 예약 크기 |
| altKo / altEn | 해당 함선과 장면을 설명하는 KO/EN 대체 문구 |
| copyright / representation | 권리자와 공식 홍보·콘셉트·인게임 이미지 구분 |
| reviewedAt / reviewStatus | 사람이 변형까지 확인한 날짜와 공개 가능 여부 |

정적 이미지 파일을 Pages의 `assets/images/ships/`에 저장하는 방식으로 시작한다. 방문자의 브라우저가 외부 RSI 주소를 매번 요청하지 않도록 한다. 추가 이미지 전용 서비스를 전제로 하지 않는다.

## 수집·검수·공개 순서

1. 검토한 RSI 공식 페이지에서 후보를 수집한다. 커뮤니티 업로드나 검색 엔진 이미지를 공식 사진으로 취급하지 않는다.
2. 제품명·제조사·canonical ID·실제 장면을 대조한다. C2/M2/A2, Mk IV/Mk V, 도색형과 한정판을 자동으로 같은 사진에 연결하지 않는다.
3. 원본 주소·해시·해상도를 기록하고, 확대 없이 카드용 약 640px / 상세용 약 1280px WebP를 만든다. 크기와 압축률은 실제 샘플의 화질·용량을 보고 조정한다.
4. 최초에는 물류 함선 5~10종을 직접 검수한 뒤 시범 공개한다. 다른 선체·도색을 대표 사진으로 쓰려면 그 관계를 명시하고 공개 화면에도 표시해야 한다.
5. 검수되지 않은 함선은 기존 텍스트 카드를 유지한다. 임의의 비슷한 사진이나 AI 생성 사진으로 빈칸을 채우지 않는다.
6. 카드 이미지는 지연 로드하고 너비·높이를 고정한다. 검색·정렬·필터·비교·격납고·플래너 연결이 유지되는지 확인한다. 상세 화면에서 권리자와 공식 출처를 제공한다.
7. 모든 ID의 유효성, 중복 연결, 공식 출처 도메인, 경로 이탈, 파일 크기·해시, 변형 오매칭, 깨진 이미지의 텍스트 대체, KO/EN 및 모바일을 검증한 후 범위를 넓힌다.

## 운영 원칙

- 이미지 확인 날짜와 Erkul 제원 동기화 날짜를 분리한다. 오래된 공식 콘셉트 사진이 최신 게임 외형을 보증하는 것처럼 표시하지 않는다.
- 원본이 달라졌다면 자동 덮어쓰기보다 변경 후보로 보관하고 다시 검토한다. 이전 공개 사진과 매핑은 Git으로 복구할 수 있게 한다.
- CMS 연결은 2단계로 두고 기존 관리자 권한과 변경 이력을 사용한다. 외부 URL을 제한 없이 입력받거나 공개 업로드 저장소를 만들지 않는다.
- 팬 콘텐츠 이용 조건은 기존 `official-imagery-manifest.json`의 정책과 공식 출처를 기준으로 다시 확인한다.

## 다음 개발 단위

**별도 매핑 + 검증기 → C2 등 5~10종 시범 → 카드·상세 UI → 전체 검수 확대 → 필요 시 CMS 관리** 순서를 권장한다. 현재 단계에서는 이 설계와 C2 원본 조회 검증까지만 완료했다.
