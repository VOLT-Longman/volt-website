# 함선DB 공식 대표 이미지 시스템

2026-10-18: 최초 5종 시범 후 전체 254개 항목을 점검해 246개로 확대했다(241개 추가, 약 96.9%). 함선·차량·컨셉 항목을 포함한다. 공식 제품 페이지 Product JSON-LD, 공식 Ship Matrix의 제품명·제품 링크와 실제 원본 장면을 대조했다. 공식 제품 홍보 사진이며 최신 게임 외형의 실시간 보증은 아니다.

## 데이터와 배포

- `data/ship-imagery.json`이 검수 목록의 유일한 원본이다. 함선 UI 고유 ID로만 연결하며 Erkul 제원 갱신과 분리한다. 도색형·한정판·파생형에 기본 선체 사진을 자동 상속하지 않는다.
- 각 레코드에 제품명, 공식 제품·원본 URL, 원본 크기와 SHA-256, 검수일과 상태, KO/EN 대체 문구, 두 로컬 파일의 크기·해상도·해시를 기록한다. `data/ship-imagery-review.json`에는 전체 254개 항목의 검수·보류 결과와 공식 페이지 증거를 남긴다. Aurora Mk I/Mk II, Constellation Mk IV/Mk V, Zeus Mk II처럼 공식 표기와 내부 이름이 다른 경우에도 세대와 파생형을 따로 확인한다.
- 원본을 확대하지 않고 WebP 640px 카드 / 1280px 상세 사진으로 변환한다. 브라우저는 외부 RSI 이미지 서버에 의존하지 않는다.
- `node scripts/build-ship-imagery.mjs`로 작은 정적 `js/ship-imagery.js`를 생성한다. `--verify` 검사는 CI의 필수 check에 포함되며 두 함선 카탈로그의 ID·제품명, 검수 기록과 정확한 제품/사진 연결, 공식 도메인·제품 경로·중복 원본·로컬 경로·파일 해시·실제 인코딩 해상도와 생성물 일치를 확인한다. 공개 스크립트에는 표시용 정보만 압축해 담는다(약 93KB, gzip 약 9.5KB).
- 카드는 지연 로드한다. 상세에서는 이미지 출처 링크와 저작권을 작게 제공한다. 미등록·오류 사진은 빈 이미지 대신 기존 텍스트 카드와 제원 화면으로 돌아간다. 사진 모듈 실패도 검색·제원을 막지 않는다.

## 확대 절차

1. 공식 제품 페이지에서 제품명·제조사·고유 ID와 실제 장면을 확인한다. 특히 C2/M2/A2, 기본형/화물형, 도색과 한정판을 구분한다.
2. 원본 URL·해시·크기를 기록하고 썸네일/상세 파일을 생성한 뒤 검수 상태를 확정한다.
3. 생성기와 필수 검사, 오류 복구·다국어·모바일·시각 검사를 통과한 다음 배포한다.
4. 공식 원본이 바뀌면 자동 덮어쓰지 않고 재검수한다. 기존 파일과 매핑은 Git에서 복구한다.
5. 나머지 함선은 검수될 때까지 기존 텍스트를 유지한다. CMS 사진 편집 기능은 아직 구현하지 않았다.

소개·가입 안내의 사진 아래 반복 문구는 제거했다. 푸터의 공식 출처·저작권·비공식 팬 사이트 안내는 유지한다.

## 이번 확대에서 보류한 8개

- 600i Executive Edition, Caterpillar Pirate, Dragonfly Star Kitten, F7C-M Hornet Heartseeker Mk II, F8A Lightning, Gladius Dunlevy: 현재 카탈로그의 개별 공식 제품 링크와 해당 모델 사진을 확정하지 못했다. 비슷한 모델이나 도색으로 채우지 않는다.
- Constellation Phoenix Emerald: 기존 공식 제품 링크가 404이며 현재 Ship Matrix에서도 해당 항목을 확정하지 못했다.
- Nautilus Solstice Edition: 공식 제품 사진을 찾았으나 전투 장면에서 대상이 작고 부분적으로 보여 정확한 대표 외형 식별이 어려워 보류했다.

보류는 공식 자료가 영구적으로 없다는 뜻이 아니다. 추가 공식 근거와 적합한 사진을 확인한 뒤 별도 검수한다. 원본 자동 수집은 공개 승인이 아니며, 새 사진은 검수 목록을 통과해야만 공개 생성물에 들어간다.
